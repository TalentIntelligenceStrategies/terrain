Primitive bench

Every core/ module against a fake host. The numbered checks below are the ones the extraction has to pass — each states what it is proving, so a failure says what broke rather than that something did.

1 · A region reserves its height and does not jump twice

waitOn captures offsetHeight before emptying. Without it the body collapses to the loader’s 20px, the grid reflows, and it reflows again when data lands — two layout jumps to say one thing arrived.

2 · A failure keeps the reserved height

failIn deliberately does not clear minHeight. Real content sets its own height; a sentence does not, and the region would collapse — which is the fault the reserve exists to prevent, at the moment it bites hardest.

3 · An identical second failure announces twice

A live region re-set to the string it already holds is a mutation several screen readers do not announce, so the second press of the same button would be silent. sayFailure clears and re-sets after 60ms. Verify with VoiceOver — the DOM check below proves the clear happened, not that it was spoken.

announced 0 times

4 · A button keeps its accessible name through a wait

The CSS hides every child with display:none, and display:none content is excluded from the accessible name computation — so for the length of the beat the button announced as a button with no name at all. Nothing visual shows it.

5 · A stale generation no-ops

A deferred callback that lands after its state has gone writes into a surface nobody is looking at. Press Start then Start again before the first lands: only the second should write.

6 · Escape unwinds in order

The stack is what makes a second overlay safe. Open three, press Escape three times, and they close most-recent first.

—

7 · REDUCED is live, and a beat is not shortened by it

Read through reduced(), never cached: the prototype read it once at parse time, so turning reduced motion on mid-session moved the CSS and left the JavaScript behind.

—

8 · The loader, at rest and in motion

One mark, one size, no variants. Under reduced motion it is present, visible and motionless — and the dots hold the positional ramp rather than going flat.

9 · failHTML offers a way forward only where there is one

The retry button is optional by rule: a block with no way forward says so by having no button rather than by having a dead one.

10 · armed cannot have an incomplete list

Registering is the only way to create a flag, so disarmAll() cannot miss one — which the hand-maintained nine-flag checklist in the router could.
